# 每日五圖｜取數眉角

**這份在 SKILL 第 3 步才需要讀。** 每一條都是實測撞出來的，
而其中一半的失效方式是安靜的 —— 那些用 **粗體** 標出來。

數字（限流、代理、歷史深度、單位換算）在 `chart/anchors.json`，這裡不抄。

## 允許的來源

| 來源 | 用途 | 金鑰 |
|---|---|---|
| FRED | 總經、利率、利差、信用、匯率、通膨預期 | `FRED_API_KEY` 或 `~/.config/fred/api_key`，**不進版控** |
| Tiingo | 美股個股與 ETF 日線 | `TIINGO_API_KEY` 或 `~/.config/tiingo/api_key`，**不進版控** |
| 證交所、櫃買 | 台股日收盤、籌碼、台灣總經 | **免金鑰、官方端點** |
| 世界銀行／IMF／EIA | 跨國、能源實體數據 | 官方 JSON／CSV |
| 公司財報、法說簡報 | 個別公司數字 | 原始文件，**不引用二手轉述** |

**一律不使用付費牆內的圖或數據。** 取論點沒問題，把對方的數字當我們的資料來源不行。

### 廣度：一個還沒量完的缺口（2026-08-22 開，尚無結論）

`data/series` 裡有 19 條非美標的與指數（三星、東京威力科創、愛德萬、`^SOX`、`^KS11`、
`^NDX`、`^RUT`、`^DJI`、`^STOXX50E`……）**全部凍在 2026-08-19** —— 那些是**曾經畫得出來、
現在畫不出來**的題目，加上這一週被砍掉的櫃買指數與美元指數。

先前查過的六家「都沒有 `^SOX`」是**專查授權**，不等於整體涵蓋率查過了。
探針在 `scripts/chart/probe_sources.py`（一次性，不在每日路徑上）：
`--sources` 量 Stooq 與 Twelve Data 的涵蓋率，`--yahoo-layer` 量封鎖是 IP 層還是客戶端層。
**沙箱出口只通 pypi，這兩支都必須在 Mac 上跑。**

**2026-08-22 第一輪實測，兩個結果性質不同：**

- **Yahoo 的封鎖是客戶端層**（詳見下一節）。yfinance 在同一台機器上拿得到 `^GSPC`。
  **2026-08-22 決定：開，但範圍極小、規則明著改。**
  規則的家在 `anchors.rate_limits`：`handshake_vs_evasion` 拆開「限流退避」與
  「必要的握手」，`handshake_allowlist` 是那五條（櫃買指數、韓綜、三星、
  東京威力科創、愛德萬）—— **只放既沒有等價序列也沒有 ETF 代理的代號**。
  `^SOX`／`^STOXX50E`／`HG=F` 有 SOXQ／FEZ／CPER，**不進清單**。
  取數走 `fetch.yahoo_handshake()`，清單以外呼叫它會被擋下來並說出為什麼。
  **用握手取到的序列，該圖 note 要寫明來源與取法**，比照 ETF 代理。
  預抓每天抓那五條，**等於每天替這條路做一次體檢**；壞了落在狀態檔的
  `handshake.failed`，當日退回代理或改題。
  **界線有一半仍然沒有量到**（Yahoo 是針對我們，還是對所有無 cookie 客戶端一律 429）——
  寫在 `handshake_vs_evasion` 裡，要改那條規則之前先把它量掉。
- **第三輪（帶 Twelve Data key ＋ `AAPL` 對照組）才是有結論的那一輪：**
  - **Stooq 出局，而且是對照組把它判掉的。** `aapl.us` 與其餘十條回的是**同一頁
    795 bytes、帶 `robots` 字樣的網頁**。對照組也失敗＝問題在端點與客戶端的關係，
    **與涵蓋率無關**。不再列入候選。
  - **Twelve Data 免費方案＝美股。** `AAPL@NASDAQ` 拿得到（30 點、落後 1 天）；
    櫃買指數、韓綜、日經、Stoxx 50 在 `symbol_search` 找不到；
    三星、東京威力科創、愛德萬回 404。**那三檔非美個股沒有回到有金鑰的來源**，
    所以 `handshake_allowlist` 維持原樣，沒有東西可以拿掉。
  - **同一輪製造了三個假的 ✓，是探針的錯不是來源的錯。** `^SOX` 被解析成
    **SOXL（Direxion 三倍槓桿半導體 ETF）**、`HG=F` 解析成 **HG（Hamilton Insurance
    Group，一家保險公司）**、`DXY` 解析成 `DXYN@OTC`。三個都回 30 點、末日正確、
    落後 1 天 —— **每一個訊號都說它成功了**。原因是探針拿 `symbol_search` 的第一個
    候選就用。已改成**只接受逐字相同的代號**，其餘把候選攤開讓人看；
    並刻意不剝 `^` 與 `=F`，因為剝掉之後 `HG=F` 會逐字命中那家保險公司。
    **這是同一個坑的第三次**（Stooq 的 JS 被讀成資料、Stooq 的網頁被讀成「沒有這條序列」、
    現在是別的商品被讀成想要的商品）：**來源回了一個看起來完全合理的答案。**
- **Stooq 前兩輪的沿革（留著是因為它解釋了對照組為什麼是必要的）：**
  第一輪十條全部回 `ValueError: could not convert string to float: 'e.encode(c+n))'` ——
  那是 JavaScript：探針當時只擋「空 body」與「No data」兩種假失敗，
  **第三種（回 HTML／JS）被讀成了「這個來源沒有這條序列」**，差一點就寫進本檔。
  第二輪修好判別後，十條回的是**同一頁 HTML、同一個 `<meta name="robots">`**：
  **回應與代號無關，所以它講的是端點與客戶端的關係，不是涵蓋率。**
  跟 Yahoo 同一類，只是換一個門。
  **這一輪的設計缺陷是沒有對照組** —— 十條都失敗時，「來源沒有」與「來源不理我們」
  在輸出上長得一模一樣。探針已補 `AAPL`（`aapl.us`）當對照組並把網頁的
  `<title>` 與 cookie／robot 字樣抄出來，**第三輪才會有 Stooq 的結論**。

**結果回來要登錄在這一節**，連同限流與落後天數 —— 沒登錄的實測，下一個人會再測一次。

所以 `~/.venvs/kb` 裡一直沒有它。08-26 至 08-29 連續四天的執行報告都記著

**握手那條路本身是好的**：四條末日都貼著最新交易日，證明客戶端層的封鎖確實靠握手解掉。

### `^TWOII` 是另一回事：它在來源端就死了

08-08 量到它落後 22 天，08-29 量到 **43 天，末日凍在 2026-07-17**。
不是固定延遲，是**這條序列在 Yahoo 上停止更新了**，而且還在惡化。

**對照組決定了這個結論**：同一天 `8069.TWO`（櫃買個股，走櫃買官方端點）末日 2026-08-27。
所以不是「櫃買資料拿不到」，是**櫃買的「指數」在 Yahoo 這條路上死了**，個股完全正常。
官方端點仍然只給個股與加權指數（＝證交所的 TAIEX），沒有櫃買指數，
FRED 無等價、也沒有 ETF 代理 —— **所以它留在 `handshake_allowlist` 裡，因為還是沒有第二條路。**

**但它從明天起會變安靜，這才是要記的部分。** 在此之前它每天落在預抓狀態檔的
`handshake.failed`，是一個大聲的失敗；裝了 yfinance 之後它會落進 `ok`，
**而它依然不能用** —— 任何用到它的圖都會被 `series_freshness` 判硬失敗。
涵蓋率會從 33/48 變成 34/48 或 35/48，看起來像進步。
**失敗沒有變好，只是變安靜了。** 用它之前先看末日，這條規矩比以前更要緊。

> **2026-09-02 追記：那個預測完全成真，而且四天沒有人動它。**
> 當天 `^TWOII` 落後 33 個交易日、末日仍是 2026-07-17，穩穩落在 `ok`、`handshake.failed` 為空。
> 值得記的是**它其實一直是可見的**：`prep_chart._stale()` 每一輪都把它印成「不能用」。
> 缺的不是偵測，是**狀態檔自己那一格的對稱性** —— `handshake` 只寫了
> 「有東西＝路壞了」，沒有寫「空的不代表好」，而讀狀態檔的人不會同時在看 prep 的輸出。
> 所以那一格加了 `handshake.stale`（走握手、取數成功、末日過硬失敗門檻），
> 判定整段委外給 `prep_chart._stale()`，**這裡不抄門檻也不另寫一份**。
> **它是量測不是閘門**：不改門檻、不擋產出。`^TWOII` 的處境一天都沒有變好 ——
> 變的只是它不再需要讀者自己把兩個段落接起來才看得見。

## 三個在這台機器上成立的事實

- **Yahoo 擋的是「沒有握手的裸客戶端」，不是這台機器**（2026-08-22 更正，見下）。
  舊寫法是「Yahoo 對本機是永久封鎖」，依據是 08-14 首測與 08-16 複測：
  兩天後、單一標的、零流量，第一個請求仍 429。
  **那個結論把客戶端的性質算成了機器的性質。**
  08-22 在同一台 Mac、同一個 IP、相隔幾秒量了兩次：
  裸 urllib＋固定 UA → 第一個請求 HTTP 429；
  yfinance（先取 cookie 與 crumb、帶瀏覽器樣標頭）→ **通了，5 點，末日 2026-08-21**。
  **判定是客戶端層。**
  兩件事這次沒有量到，不要當成已知：**(1)** Yahoo 是針對我們，
  還是現在對所有無 cookie 的客戶端一律 429（若是後者，「規避」這個詞用錯了，
  那是握手不是繞路）；**(2)** 握手流程能撐多久 —— yfinance 每隔幾個月被 Yahoo 改壞一次。
  **連帶影響哨兵**：預抓每天用裸客戶端試 `^GSPC`，它問的是「裸客戶端通不通」，
  不是「Yahoo 通不通」。若 Yahoo 從此要求握手，**這個哨兵永遠只會回同一個答案** ——
  一條只說得出一種話的檢查，跟沒有檢查一樣。
  等價序列對照（`^VIX`→`VIXCLS`、`^GSPC`→`SP500` 等）在 `fetch.py`；
  台股個股與美股 ETF **沒有 FRED 等價**。
  **要不要因此採用 yfinance 是一個還沒做的決定**，見上一節。
- **`fredgraph.csv` 在發布機上連不通**（`Errno 60`），而 `api.stlouisfed.org` 正常。
  **在這台機器上，退路才是壞的那一條** —— FRED API key 是這條線的唯一活路。
  若某輪回報「無 API key，走 fredgraph 退回端點」，**先確認那輪跑在沙箱還是發布機**。
- **FRED 一次只能抓一條序列。** `fredgraph.csv?id=A,B` 回傳的是 zip。

## 安靜失敗的那些

- **櫃買被節流時回空 body，不是錯誤碼。** 空不是「沒有資料」，是被擋。
  取數層要重試並在最後誠實拋錯，**不回空序列**。
- **證交所日期送錯不會報錯，會安靜回最近一個交易日。** 務必核對回傳的 `title`。
- **櫃買的成交量欄位名稱會隨年代改變**（近年「成交張數」、2016 年「成交仟股」），
  要讀 `flagField` 判單位 —— 與融資餘額「仟元 vs 元」同類，
  **差 1,000 倍而數字看起來都像個數字**。
- **Yahoo 期貨日線會整日空值**（2026-08-06 實測六支全空）。
  **空值那天直接跳過，不要內插、不要拿前一日頂替**，並寫進 `window.note`。
  **不要照原樣出圖再用「轉倉」搪塞。**
- **民國年轉換錯了不會報錯**，只會讓整條序列偏到 1911 年代。
- **台股路線的歷史深度是我們自己傳的參數，不是來源給的。**（2026-09-02）
  證交所與櫃買的端點逐月取，所以「要幾個月」由呼叫端決定 —— 而在那天之前
  **沒有人傳過**：`fetch_tw_price.series()` 的預設是 `months=24`，`fetch.get()` 不帶它，
  於是七條台股快取（`^TWII`、2330、2317、2344、2382、2408、8069.TWO）
  **全部起於 2024-09-02、跨距剛好 2.00 年**，而同一天其他路線是 5.22–11.66 年。
  值現在在 `anchors.history_limits.tw_route_months`（36）。
  **它藏住的方式是「上限只活在一個函式的預設參數裡」** —— `history_limits` 那一格
  （讀表的人唯一會來找的地方）從來沒有它，所以台股的分位被當成跟其他列同一把尺用了。
  **改那個數字不會補到歷史**：`have_through` 非空時走增量，只從快取末日數到本月，
  歷史那一段永遠不會被要求。補歷史走 `scripts/chart/backfill_tw_history.py`
  （強制 `have_through=""` 全量，經 `fetch.merge_write()` 的聯集守衛寫回，預設一次兩條）。

## 兩件容易被弄反的事

- **回空殼與被封鎖是兩件事，處置相反。** 前者換讀法、後者換來源。
  把前者誤判成後者，等於白白放棄一個可用的來源 —— Bloomberg Graphics 就這樣被閒置了七天。
- **同樣是 429，成因可能完全不同。** 第一個請求就 429 → 等再久也不會好；
  打了一陣子才 429 → 那是該等的那種。**分辨方式是看它第幾次請求才出現。**

## 瀏覽器路徑

- **`navigate` 到 JSON 網址會被 Chrome 當檔案下載**；改 `fetch` 之後**跨子網域會被 CORS 擋**。
  正解是**先 `navigate` 到同網域頁面再 `javascript_tool` fetch**。
- **證交所／櫃買不允許跨源，但同源可用。** 先前把限制寫成「CORS 使瀏覽器備援無效」是寫過頭了 ——
  **把限制寫得比實際寬，會讓人在真正需要備援時直接放棄一條可用的路。**
- **瀏覽器備援需要人在場，無人值守輪次實際上不可用。** 2026-08-14 那輪就因為當下沒有 Chrome
  而完全沒有產出。所以 `about.data_path` 走到 `browser` 是**該響的**，不是降級。

## 代理

沒有免費來源的指數用 ETF 代理，對照表在 `anchors.proxies`。

**代理必須在 `series_spec` 明寫，不由取數層自動替換。**
曾經寫成「`^SOX` 取不到就改抓 `SOXQ`」，那會把 ETF 的資料寫進指數的快取，
**圖上標的是指數、數字卻是 ETF**。**替換要是一個有意識的決定，不是取數層的靜默行為。**

用代理時錨點措辭要跟著限縮（歷史深度在 `anchors.history_limits`）——
`SOXQ` 只回到 2021 年成立，**不可寫「歷史上」或「十年分位」**。
