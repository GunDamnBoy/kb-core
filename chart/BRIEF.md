# 每日五圖｜什麼算對的產出

每一個數字在 `chart/anchors.json`；怎麼做出來在 `skills/chart/SKILL.md`；
取數眉角在 `chart/SOURCES.md`。**這份只講「什麼算對」，不講「怎麼做」。**

## 一、這套系統的身分

每天挑五個題目，用公開資料**自己重製**五張圖，每張圖配一段自己的判讀。

三件事同時成立才算數，缺一張圖就不算：

1. **圖是自己重製的。** 選題可取材自 Bloomberg、FT、Economist，**絕不轉載他們的圖**。
2. **每張圖都要有「所以呢」。** `takeaway`／`so_what`／`watch` 三欄必填。
3. **資料留得住。** 任何一天的圖，一年後都要能原樣重畫。

上游是投顧知識庫（提供當日題材），下游是 convergence-weekly 與 House View 月報
（**pptx 直接取用 `charts/<date>/*.png`**，所以那個路徑是對外契約）。

## 二、每天產出的是資料，不是圖片

`data/YYYY-MM-DD.json` 一天一檔、**永久保留、發布後不改寫**。
要修正就發新的一天，並在 `about.run` 說明。

`charts/<date>/` 的 PNG 與 SVG 是**從那份 JSON 算出來的**，不是另一份真相。

### 一份 spec，兩個渲染器

靜態軌（PNG／SVG）與互動軌（網頁）**從同一份 spec 出圖**，而日檔**把算出來的 option 一起存下來**
（`anchors.rendering.stored_option`）。

理由是舊制的頭號缺陷：**雙軌漂移**——改了靜態軌忘了互動軌。
最嚴重的一次是瀑布圖在網頁上每根從 0 往上長，**圖上的結論與 `takeaway` 相反，
卻不丟任何例外**。兩種錯的代價不對稱：雙軌漂移是正確性失效，
而「舊圖用新版渲染器重畫會有樣式差異」只是版本問題——所以 `about` 記 `renderer_version`。

**存 option 不是為了省事，是為了讓漂移驗得到**：檢查 `chart.option_matches_spec`
問的正是「這份 option 有沒有忠實地把 spec 編碼進去」，四條斷言在
`anchors.rendering.drift_assertions`，每一條都是從真實事故反推的。**沒有 option 就沒有東西可以驗。**

> **2026-08-30 更正。** 這一段原本寫著「日檔不存 option」與「2026-08-05 至 08-17 那 13 天存了 option，
> 所以渲染層吃兩種方言」。**兩句都是錯的，而且錯了十天沒有人發現。**
> 實測 23 份封存日檔：**每一份的 5 張圖都有 option**（近十期穩定佔檔案的 21–23%，
> 08-06 那期到 50%）。正確的沿革在 `CHANGELOG` 2026-08-20 深夜〈架構改判：兩軌都留〉——
> `stored_option` 當時就從 false 改回 true、`chart.no_stored_option` 換成 `chart.option_matches_spec`，
> **而 anchors 與程式跟上了，這份沒有。**
> 危險的不是文字錯，是**這份是「什麼算對的產出」的正本**：照它做把 option 拿掉，
> 那四條斷言會整組失效，而失效的樣子是「檢查全綠」。

那 13 天真正的另一種方言是**序列化格式**（compact vs `indent=1`），
見 `anchors.rendering.legacy_json_format`。

### 資料欄位逐圖型不同

`series` 只是 timeseries 的欄位。scatter 用 `pts`、heatmap 用 `cats`/`rows`/`matrix`、
長條用 `cats`/`groups`。**完整對照在 `anchors.json` 的 `kinds`**，渲染層與檢查程式都照它走。

## 三、五個 slot 與五條軌道

順序固定：當日主圖／市場異動圖／重製圖／主題深掘／軌道圖。

- **五張圖不得有兩張同 `theme`**，週末同樣適用；撞了就換掉排序較後那張。
- **slot 1、2、4 必須是當天的事。** 素材不足時改「前瞻框架」並在 `about.run` 記錄，不是硬湊。
- **slot 3 的原題七天內，但我們的圖必須用最新資料。**
  原題可以是三天前的專題，**我們的圖不行是三天前的圖**。
- **軌道綁死週一至週五**（值在 anchors）。週末不推進輪盤、改週線複查，
  且**週六與週日不得挑同一條**——「同一條軌道每週固定同一天出現」才有跨期可比。

## 四、份量與圖型

長度區間全部在 `anchors.json` 的 `lengths`。三件事值得單獨講：

- **`title` 是一個判斷，不是標籤。**
- **`so_what` 不准寫「須密切關注」這種空話。**
- **每期至少一張非折線。** 但**若當天真的每個題目都是兩條線的關係，
  要換的是選題角度，不是硬換圖型**——為了滿足規則把不適合的資料塞進雷達圖，比五張折線更糟。

序列**最多四條**（值在 anchors）。上限是配色決定的：只有四個角色，
第五條會繞回主角紅，一張圖出現兩個主角。**超過就拆圖，不是換色。**

## 五、判讀怎麼寫

- **數字一律來自我們自己算出來的序列，不是抄新聞。** 與媒體不一致時兩個都寫並說明計算基準。
- **不要引用本圖序列涵蓋不到的日期。** 若那個數字其實是抄來的，刪掉它。
- **說得出是哪一次的才叫歷史。** 「歷史上通常」「經驗上」說不出年份的，是印象不是歷史。
- **類比必須成對出現：相同點＋關鍵差異。** 寫不出關鍵差異就把這個類比刪掉。
- 寫「可能」「或許」時問自己**怎樣才算錯**，寫不出來就刪掉那句。
- **不要讓 slot 3 變成別人電子報的翻譯。** 取它的題目，**問題要自己重新提**。
- 全程繁體中文（台灣用語）。不用 emoji，不用「驚人」「暴漲」這類形容詞去補說服力不足的地方。

## 六、當期失敗判準

任一條成立，這一期就是失敗，照實記錄在 `about.run`：

1. 五張圖裡有兩張同 `theme`
2. 五張全是折線（2026-08-10 起）
3. 有序列落後超過硬失敗門檻（日頻／月頻兩套，值在 anchors）
4. 有圖的資料欄位缺席（依 `kinds` 判，缺了就畫不出來也重畫不出來）
5. `about.data_path` 沒填

## 七、合規紅線

- **不轉載國際媒體的圖。** 取材可以，資料一律自己抓、自己算。
- **一律不使用付費牆內的圖或數據。** 取論點沒問題，把對方的數字當我們的資料來源不行。
- **429 是對方在說「慢一點」。等，不要繞。** 不可以換 host、不可以加碼重試。
  持續未解就降級或改題並寫明——**寧可誠實少一張圖，也不要繞。**
- **「限流退避」與「必要的握手」是兩件事**（2026-08-22 拆開，界線與允許清單在
  `anchors.rate_limits`）。握手只走清單上那幾條**既無等價序列也無 ETF 代理**的代號，
  **用了要在 note 寫明來源與取法**，比照 ETF 代理。清單以外一律照上一條。

## 八、`about` 記什麼

`data_path`（prefetch／direct／browser 三選一）、`renderer_version`、
本期的降級與其理由、素材不足的具名記錄、QA 旗標的處置。

**`about.run` 的自述不能當查核依據**——凡是規格有數字、而執行端會自述「我有照做」的地方，
都該有一個獨立的量測。
