# 派工單共通部分｜給每一位撰寫 subagent

> **正本在 `kb-core/scripts/podcast/dispatch-common.md`**（2026-10-03 新增）。主代理每天把它和
> `preamble.md` 一起交給撰寫 subagent，再另外附上**該集的機械事實**（路徑、篇幅級距、壓縮比、
> dupmap 那一段、主持人候選、交件路徑與工作目錄）。**這份只放每天都一樣的部分**；
> 規則全文在 `preamble.md`，本檔不重抄規則，只補交件格式與無人值守的硬規則。

你是 podcast 日報某一集的撰寫者。**先用 Read 完整讀完 `preamble.md`（全文，不要只讀片段）**，
那份就是全部規則；派工單會告訴你它在哪個路徑。

## 交件格式（JSON 片段，用 Write 寫到派工單給的交件路徑；不要只寫在回覆正文）

```json
{
  "titleZh": "中文標題（不含節目名，組檔者會加上「節目名｜」）",
  "hosts": "依稿判定的主持人（名單只是候選）；判定不了寫節目名",
  "guest": "一句話描述來賓與單位；沒有來賓寫空字串",
  "guests": [{"name": "照節目說法", "affiliation": "判斷不了留空字串"}],
  "source": "給人讀的來源說明：用了哪份稿、退回原因、照缺漏處理的區間（時間戳＋段號）、是否重播",
  "sourceLayer": "<整數 1–4：實際用的退援層級。1＝官方稿、2＝podfetch 稿、3＝YouTube 字幕、4＝精簡摘要。和篇幅級距無關>",
  "summary": "一段，抓住全集最重要的張力，不要流水帳",
  "sections": [{"heading": "章節標題", "paragraphs": ["段落", "段落"]}],
  "takeaways": [{"title": "標題", "body": "兩到四句，必須含對投資人的含義"}],
  "quotes": [{"text": "中譯", "by": "講者姓名（判定不了寫節目名或角色）", "original": "podfetch 稿單行內的原句，一字不改"}],
  "topics": ["只能從 preamble 第六節的十五個裡選 1–3 個"],
  "quality": {"speakerNote": "講者標記問題與名單不符（具名）", "timestampNote": "時間軸／重複／缺漏／自編段的自查結果"},
  "report": "狀況回報：寫了幾段、退援層級與退回原因、是否下界例外（逐字稿幾字、寫了幾段、理由一句話）、三種循環重複訊號各自結果、主持人名單不符、其他下游該知道的事"
}
```

- **`sourceLayer` 填整數（例如 `2`），不要照抄上面那串說明文字。** `checks/podcast.py` 用 `== 1` 判斷官方稿容許，字串會安靜判成不是 1。
- **`sourceLayer` 是退援層級，不是篇幅級距。** 派工單講篇幅一律寫「篇幅級距 N」，
  **「第 N 層」只指退援層級**。2026-10-03 有一集把它填成篇幅的層數，而這個欄位決定篇幅閘門給不給一成容許。
- `quality` 只寫 `speakerNote` 與 `timestampNote`；`completeness`／`status` 由組檔者照抄 manifest。
- 數量照派工單（`takeaways`／`quotes`／`topics` 的上下界）；`summary` 一段。
- 字數定義：`sections[].paragraphs[]` 串接後的字元數（含標點空白）。組檔者會用 python 量；
  你可以自己量一次來規劃，但收斂只做一次（preamble 第一之二節）。
- **交件前用 python 把每條 `quotes[].original` 對 podfetch 稿做 `original.strip() in text` 比對，全部 True 才交。**
- 寫完用 `wc -c` 確認落地，交件訊息寫出檔案大小與 `report` 的內容。**交件之後組檔者無法追問你**，一次給足。

## 工作目錄：只用派工單給你的那一個

**你寫的任何暫存檔（腳本、草稿、量測輸出）一律放在派工單指定的「工作目錄」底下，
不要寫進共用的暫存區或 `outputs/` 根目錄，也不要執行不是你自己寫的腳本。**
2026-10-03 十二個 subagent 共用同一個暫存區，一個 subagent 寫的 `build.py` 被另一個同名覆寫、
誤跑之後把**別集**的交件檔重寫了一次——內容剛好沒壞，但那是運氣。

## 無人值守的硬規則

- **不要呼叫任何 `request_access`，不要用內建瀏覽器（`Claude_Browser` 系列）。** 需要核准的動作在無人值守下會掛住整輪。
- 派工單沒叫你上網就不要上網；叫你上網時只走它指定的那條路，走不通就照派工單退回。
- 不跑任何 git 指令；除了交件檔與工作目錄，不寫任何檔案。
- 不憑印象編造內容或引述；判定不了講者就不要猜人名。
- 標為「照缺漏處理」的區間：不要據它生成內容，並在 `source`／`timestampNote`／`report` 具名。
- 派工單的「乾淨」只是訊號：自己跑三個循環重複訊號（行數÷總字數、原地打轉、末端時間戳對片長），
  並讀一次片尾之後與各段段尾有沒有自編段（preamble 第九節），結果寫進 `report` 與 `timestampNote`。
