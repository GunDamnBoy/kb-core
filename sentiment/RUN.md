# 怎麼跑這幾支探測

**為什麼要你跑**：Cowork 這一側的對外連線只通 GitHub 與 PyPI，
TWSE／TAIFEX／FRED／Stooq 全部不通（雲端容器與 device bash 兩邊都試過，`curl` 皆回 000）。
下面幾支要在**你的 Mac 終端機**跑。

程式在 `~/kb-core/scripts/sentiment/`。

> **貼指令時不要連註解一起貼。**
> zsh 互動模式預設**沒有開 `interactive_comments`**，所以行尾的 `#` 不會被當註解，
> 會被當成參數送進 python，然後你會看到 `unrecognized arguments: # ...`。
> 這一頁的每個區塊都已經拿掉行內註解，整段複製貼上就好。

## 前置

```
python3 -m pip install --user numpy pandas scipy
```

## 第 0 步：先量通不通（三十秒）

**先跑這個，不要直接跑 --fetch。** 抓到一半才發現某個來源不通，代價是一小時。

```
cd ~/kb-core/scripts/sentiment
export SENT_CACHE=~/sent-cache
python3 netcheck.py
```

把整張表貼回來。**哪一項不通會改變下一步做什麼**，不是只是換個寫法再試一次：

- **TWSE 三支不通** → 台股籌碼整個做不了，要改用別的路徑（先別跑 `--fetch`）。
- **TAIFEX 三大法人不通** → 外資期貨未平倉降候補，用三大法人現貨買賣超遞補。
- **FRED 不通** → 第 2 步（觸發器）要換來源或改在 GitHub Actions 上跑。
- **只有 GitHub 通** → 跟 Cowork 這一側一樣，代表是網路層的限制不是程式問題。

## 第 1 步：台股籌碼（netcheck 的 TWSE 三支都通才跑）

```
cd ~/kb-core/scripts/sentiment
export SENT_CACHE=~/sent-cache
export SENT_GAP=0.4
python3 tw_probe.py --fetch
```

> **一次只跑一個抓取行程。**
> 2026-08-22 踩過：一邊跑 `--fetch`、一邊在另一個分頁跑診斷腳本，
> 兩個行程一起打 TWSE 觸發限流（HTTP 428），然後**我拿那個被自己汙染的讀數
> 去診斷**，花了三輪在解一個不存在的速率問題。
> 實測乾淨環境下每筆 0.44 秒、連打 15 次零失敗。
> **量測之前先把已知的干擾源關掉。**

逐日補 2014 起的融資餘額、當沖占比、外資期貨未平倉，
約 3,000 個交易日 × 3 支端點，實測約 45–70 分鐘。
**中途可以 Ctrl-C，快取會保留，再跑一次接著補。** 每 20 筆存一次檔。
被回 428 時會自動冷卻並把間隔調大（只調大不調回）。

抓完跑分析：

```
python3 tw_probe.py --analyze
```

整段輸出貼回來。特別注意三行：

- `fut_oi: 有值 N 筆` —— N 小於 100 代表外資期貨未平倉拿不到歷史，那項降候補。
  這是設計書第九節的頭號待驗項。
- `可用成分：…（設計書列 3 項，本次 N 項）`
- T3 那行的「合成有加值／合成沒有加值」

## 第 2 步：觸發器與 CAPE 分層（netcheck 的 FRED 通才跑）

```
cd ~/kb-core/scripts/sentiment
python3 trigger_probe.py
```

幾分鐘跑完。要看的是：

- **「歷史上同時亮 ≥N 盞的月數」** —— 設計書第十三節要的就是這個數字。
  我的預期是 ≥3 盞落在 2000、2007、2022 附近，也就是 n≈3。
  若真的只有 3 段，分層結論只能當「引用」不能當「證明」。
- 極端恐懼在「觸發器 0–1 盞」與「≥2 盞」之間，12 個月中位報酬與最差值差多少。
  差得夠開，第十三節的假設成立；差不開就整組退役。

## 若某支失敗

**貼錯誤訊息回來，不要自己改參數重跑。**
這幾支的設計是「抓不到就空著、不插補」，所以失敗會明講失敗。
真正危險的是有人為了讓它跑完而把門檻放寬或把重試次數調到很大——
**那會產出一個看起來很合理的假結果。**

## 這兩步之後

- 台股籌碼**有訊號** → 接著做美股週頻部位層（COT／ICI／AAII），那也是部位不是價格。
- 台股籌碼**也沒有訊號** → 照設計書第十節辦：不發布合成分數，
  儀表板降級成誠實呈現原始序列。
  **一個沒有前瞻資訊的 0–100 分數比沒有分數更糟，因為它看起來像結論。**
