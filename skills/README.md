# 排程執行的 run skill

這個目錄放的是**四套系統各自「今天／這一期怎麼做出來」的正本**。
`maintain/` 是另一回事（維護工作階段用的），不在這張表上。

| 目錄 | 排程 | 頻率 |
|---|---|---|
| `advisory/` | 投顧知識庫日報 | 每天台北 07:30 |
| `chart/` | 每日五圖 | 每天台北 11:30 |
| `bubble/` | AI 泡沫監控質化覆核 | 每週一台北 09:03 |
| `convergence/` | 主題匯流訊號報 | 每週一台北 15:00 |
| `houseview/` | 國際市場 House View 月報 | **手動啟動，沒有排程** |

> `houseview/` 是唯一手動啟動的一套：每月產出時點不固定，由 Kenny 決定。
> 它的健康檢查有一條**反向守門**——規格被寫回 cron 或排程字樣就 FAIL，
> 理由是「規格說有排程、系統卻沒有，比沒有排程更危險」。
> 下面那一節講的是另外四套。

## 另外四套全部跑在 Mac 上，建立排程時**一定要夾帶資料夾**

Cowork 的排程有兩種，而它們**在同一個介面裡建立、長得一樣**：

| | 夾了資料夾 | 沒夾資料夾 |
|---|---|---|
| 在哪跑 | 這台 Mac | Anthropic 的雲端容器 |
| 看得到 `~/outbox` | 是 | **否** |
| 出現在 `list_triggers` | 否（存在桌面本機） | 是 |

**沒夾資料夾的那一種拿不到本機檔案**：整個 `mcp__remote-devices__*` 命名空間
在排程 session 裡不存在（2026-08-23 三次獨立測量，其中一次帶
`requires_local_device: true` 也一樣）。

**而它失敗的樣子跟成功一模一樣**：那一輪照樣做完研究、照樣寫出漂亮的交付訊息，
只是草稿沒有落地 —— 沒有草稿、沒有回執、網站不更新。
2026-08-17 泡沫監控那次沒發布出去就是這個形狀，而它被發現是因為有人去看網站，
不是因為任何一條檢查叫了。

投顧與五圖從一開始就是夾資料夾的本機排程，所以每天都正常。
泡沫與匯流是後來加的，走了雲端那條路 —— **兩套週頻的都壞了，兩套日頻的都好的，
這個分佈本身就是線索**，而它被當成巧合了三個星期。

## 排時刻的第二個約束：避開用量尖峰

上游到齊的時間決定**下界**，Cowork 的用量尖峰決定**上界**。

尖峰是**平日 5:00–11:00 AM PT**，換算台北是 **20:00 到隔天 02:00**（夏令時；
PT 轉冬令時會整段往後挪一小時，那時要重算）。踩在裡面的排程消耗會明顯變快。

四套目前全部在離峰 —— 但那不是自然發生的：匯流原訂週一 21:00，正好在尖峰第一個小時，
是排程介面自己跳警告才發現的。**加第五套時把這條跟「上游到齊沒」一起算**，
兩個邊界夾出來的中間才是時點。

## 第三個約束：一場 session 只裝一件事

2026-08-23 拿真實逐字稿量出來：**context 是累積的**，每一個工具結果都留在窗口裡、
之後每一輪都要重讀。所以單輪成本一路長：

    輪次區段        每輪平均 context
      1– 76              112k
    305–380              400k
    533–608              625k

重讀佔原始 token 的 **98%**，而開場與第 600 輪的單輪成本差 **7.6 倍**。
成本函數是「context 隨輪次成長」的積分，不是「產出多少字」。

**排程執行本來就不長**（chart 179 輪、podcast 89 輪）。長的是維護對話——
實測一場 567 輪、187M，**等於五天的 chart**。所以這條規則的對象是坐在這裡的人。

「覺得有點長了就切」不可操作，所以有一支當場算得出來的：

```
python3 ~/kb-core/tools/session_cost.py            # 再做 100 輪
python3 ~/kb-core/tools/session_cost.py --next 50  # 只打算再做 50 輪
```

它用**這一場自己的資料**擬合成長率，給兩個估算：留在這裡 vs 現在新開一場。
實測 612 輪那一場，再做 100 輪是 70.3M 對 13.5M——**差 81%**。
新開一場的代價是把脈絡重講一次（幾輪、幾萬 token），跟那個數字比就知道值不值。

**逐字稿在哪一台機器上，這支就要在哪一台跑**（Cowork 是 Mac，見它的錯誤訊息）。

## 每一份的形狀是同一個

1. frontmatter 寫「每天／每週 X 台北 HH:MM 在 Mac mini 上執行」
2. 開頭指到那一套的規格檔（`BRIEF.md`／`AGENT_BRIEF.md`），並寫明衝突時以誰為準
3. 一句「排程開的是全新對話、沒有任何記憶」
4. 一句「這份文件的正本在這裡，排程裡那一份是副本」—— **改了正本沒重貼就是下一輪的漂移**
5. 地形表：上游／這一輪／發布，各自有什麼、沒什麼
6. 步驟，每一步有**完成條件**
7. **交出草稿到 `~/outbox/<系統>/`，不推 GitHub、不跑 git**
8. **等回執**，附退出碼對照表

第 7 與第 8 是硬要求：發布的閘門在 `publish.py`（泡沫是 `auto_publish.py`）那一側，
run skill 這一側直接推等於繞過閘門。

## 加第五套的時候

先問「它要不要碰本機檔案」。要 —— 就是夾資料夾的本機排程，抄上面的形狀。
**不要用 `create_trigger` 建**：那個工具沒有 folder 參數，建出來的一律是雲端任務。
