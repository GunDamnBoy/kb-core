# 國際市場 House View｜這一期怎麼做出來

**什麼算對的產出**在 `~/houseview/HOUSEVIEW_BRIEF.md`；
**縱深寫到什麼程度才算數**的範本在 `~/houseview/style-exemplar.md`（第 3 步才開）。

**這份文件的正本在 `kb-core/skills/houseview/SKILL.md`。**
2026-08-23 之前它住在 `HOUSEVIEW_BRIEF.md` 第 7 節，與規格同一個檔——
**規格與流程放同一份，等於改一邊就要記得改另一邊**，而那是這一套自己記著的失效模式。
第 7 節已退場。

## 手動啟動，沒有排程

每月產出時點不固定，由 Kenny 決定（通常在月底前留給同仁足夠的排版時間）。

**不要在任何地方寫回 cron 運算式或建立排程觸發器。**
規格說有排程、系統卻沒有，比沒有排程更危險——它會讓人以為每個月會自動有初稿。
2026-08-23 剛好又被印證一次：兩套「規格說有排程」的系統，實際上三個星期沒有把
草稿送出去過，而每一份交付訊息都看起來正常。

## 產出兩份，而且**先寫講稿再排版**

| 產出 | 誰用 | 承載什麼 |
|---|---|---|
| `script-YYYY-MM.docx` | 你（報告人） | **深度**：四區塊的逐頁講稿 |
| `houseview-YYYY-MM-draft.pptx` | 全策組同仁 | 版面與圖，交出去補圖改字 |

**順序不能反。** 讓深度決定哪幾頁值得做、要放什麼圖；反過來就是「已經排好的版面
限制了能講多深」。v3 就是在這裡走錯：它為了把散文塞進投影片，去改造畫布、格線與
密度——**深度需要的是版面之外的空間，不是更大的版面。**

## 第 1 步：備料

```bash
python3 ~/houseview/market_data.py YYYY-MM
python3 ~/houseview/prep_hv.py YYYY-MM
```

`market_data.py` 的參數必填，不帶只印說明並 exit 1。**這支必須在 Mac 上跑。**

`prep_hv.py` 產出 `prep-YYYY-MM.md` 五節：①每日五圖盤點表 ②上一期骨架（含 2.1 verdict
對帳、2.2 配置立場表）③market data ④**匯流訊號報當月各期** ⑤**外資報告當月各週**。

上游沒掛上就先 clone，並設好環境變數：

```bash
git clone --depth 1 https://github.com/GunDamnBoy/chart-of-the-day cod && export CHART_REPO=$PWD/cod
git clone --depth 1 https://github.com/GunDamnBoy/convergence-weekly cw && export CONVERGENCE_REPO=$PWD/cw
git clone --depth 1 https://github.com/GunDamnBoy/broker-research-digest res && export RESEARCH_REPO=$PWD/res
```

`CHART_REPO` 不設，相對路徑會以 `~/chart-of-the-day` 為根，整批圖找不到、產生器直接中止。

**完成條件**：`prep-YYYY-MM.md` 的五節都有內容；缺庫時 prep 會大聲說，不要略過那行。

## 第 2 步：分層取材——這一步做錯，後面全部是重複計票

**匯流訊號報的上游就是投顧、節目、泡沫、每日五圖、外資報告這五庫。**
同時讀兩層等於同一批素材算兩次票。

| 層 | 權威 | 從哪拿 |
|---|---|---|
| **敘事／判斷** | 匯流當月各期 | `prep` 第 4 節 |
| **數字** | 原庫 | `prep` 第 1、3 節 ＋ 第 2.5 步的搜尋 |
| **賣方原句** | 外資報告 | `prep` 第 5 節 |

**三條硬規則：**

1. 引了匯流的結論，**就不能再說「而且投顧與節目也這樣講」**——那是同一票。
2. **不從匯流抄數字。** 它是週頻快照，月底一定過期，抄進月報之後那個數字沒有任何來源對得上。
3. **不重做券商之間的綜合。** `crosscut` 已經做了，把它當一票。

## 第 2.5 步：兩路平行搜尋（不可省略）

知識庫拿不到完整月線數字——投顧庫只保留約三天封存檔。**兩邊打架時取搜尋。**

- **子代理 A**：當月各市場的具體數字。輸出「【項目】數字｜日期｜來源媒體」一行一則。
  `market_data.py` 已取到的不必重找。另列可自畫圖的公開資料源（見 BRIEF §5 的清單）。
- **子代理 B**：3–5 個焦點候選。先看當月每日五圖的 `watch` 與 `so_what`——
  **`watch` 是可證偽條件的素材不是成品**：上游只要求「有數字**或事件名**」，
  所以會出現「布蘭特能否守住 7 月低點區間」這種沒有門檻的寫法，沿用前先補成有數字的。

**兩者都嚴格要求：查不到就寫「查無」，不要用訓練資料填補。**
這條也約束你自己——**錯的數字比缺的數字傷害大得多**，歷史數字（年份、幅度、次序）同樣適用。

## 第 3 步：寫講稿 `script-YYYY-MM.json`

**這是這一輪的主線工作。** schema 見 BRIEF §10。

每頁四區塊：

| 區塊 | 必要條件 |
|---|---|
| **【金句】** | 一句可以直接說出口的判斷。不用「值得持續觀察」這類把判斷推給讀者的收尾 |
| **【講稿】** | 口語化逐字稿，**至少一個縱深手法**、至少 900 字 |
| **【落地】** | 對配置的含義，**依題材自由編排**，不固定分類 |
| **【可證偽條件】** | 每條要有**數字門檻**與**現值**，**恰好一條標 `primary`** |

**九個縱深手法**（正本在 `kb-core/checks/houseview.py` 的 `DEVICES`）：
歷史前例錨定／類比之後給反類比／機構行為模式／罕見度量尺／歷史警語／
指標失效檢驗／學理框架錨定／前例提煉判讀規則／層級升格。
每頁自報用了哪幾個，**全冊至少六種不同手法出現過**。
全冊層級的「三數字定錨」：開場三個數字定調，**【策略】章收尾回收同樣那三個**。

### 賣方素材：並陳 → 表態 → 理由

外資報告最貴的部分是**跨券商分歧**，而它最容易退化成一句「市場看法分歧」。三段缺一不可：

1. **並陳**：各家原話，**具名到券商＋報告名＋日期**，並指出**什麼時候什麼數字會裁決它**
2. **表態**：我們站哪一邊，一句判斷句
3. **理由**：為什麼——**至少用一個縱深手法**

同意某一家也算表態，但**理由必須是我們自己的**。
「我們同意高盛，因為高盛這樣說」不算——那是拿別人的結論當自己的理由。

**表態要進帳本**：完整表態的分歧，我們那一邊寫進【可證偽條件】，每期 3–5 條。
不表態的分歧每期至多 3 條，**且每條要寫明「為什麼我們沒有比市場更好的資訊」**。
誠實說「這題我們沒有優勢」有價值，假裝有觀點沒有——但要說得出為什麼。

**與匯流不一致時要明寫**「本月我們與匯流第 N 期的判斷不同，理由是⋯」，
不可以靜靜挑一邊。兩個裁判判同一場而讀者不知道有兩個裁判，比不一致本身更糟。

### `**紅字**` 是品牌紅強調，不是 markdown 的粗體

**單段至多 2 處、單頁帶紅字的段落不超過一半。** 2026-08-23 首次渲染時
29/32 段都是紅的，因為寫的時候當成粗體在用。近半段落都是紅粗體時，強調就失去層級。

**完成條件**：`script-YYYY-MM.json` 寫好，且第 5 步的驗證通過。

## 第 4 步：依講稿排版 `content-YYYY-MM.json`

schema 見 BRIEF §8。**頁面與講稿一一對應（標題逐字相同）**——
`script_content_aligned` 會驗，投影片多出來的那幾頁代表有頁面沒有想過要講什麼。

版面規則見 BRIEF §1。**版面不寫死**：該有幾張圖、要不要放表、象限怎麼切，
由當月素材決定。規格管的是不變的那幾條——每個 exhibit 要有判斷小標、
每頁要有 lede、密度別掉到只剩文字、紅色只出現在該出現的地方。

## 第 5 步：驗證（四項都要做）

```bash
python3 ~/kb-core/tools/houseview_verify.py --period YYYY-MM --dir ~/houseview
node ~/houseview/build_script.js script-YYYY-MM.json script-YYYY-MM.docx
node ~/houseview/build_hv3.js content-YYYY-MM.json houseview-YYYY-MM-draft.pptx
```

a) **`houseview_verify.py` 先跑**，不要帶著 FAIL 往下走。
   **SKIPPED 不是 PASS**——它說的是「這一條沒有被執行過」。
b) pptx skill 的 `validate.py`。
c) **轉 PDF、`pdftoppm` 出圖，叫子代理逐頁看圖**：疊字／溢出／壓頁尾／死白／
   標籤重疊／圓點不一致。**彩虹那個 bug 是逐頁看圖抓到的，靜態檢查看不出來。**
d) **數字回查**：每一個數字都要能在搜尋結果、`market_data.py` 輸出、或 `prep` 裡找到。

**完成條件**：`houseview_verify.py` 回報 0 FAIL、兩支產生器都寫出檔案、逐頁看過圖。

## 第 6 步：交付

`SendUserFile` 交**兩個檔**（pptx 與 docx），訊息五行：

1. 本月最重要的判斷
2. 挑了哪 1–2 個焦點議題與理由
3. 哪幾章需要補 Bloomberg 圖
4. 【驗收】兩張記分卡的統計：**我們的**（成立／不成立／未到期）與**賣方的**
   （應驗／部分應驗／落空／無法驗證，來自 `prep` 5.1）
5. 這一期用到幾種縱深手法、少的是哪幾種

## 這一輪不做的事

- **不要重述新聞。** 每一條都要有推論那一層。
- **不要寫「值得持續觀察」。** 那是把判斷推給讀者。
- **不要在【驗收】用「部分成立」。** 我們自己的記分卡只有成立／不成立／未到期——
  記分卡一旦允許模糊評級，就會退化成每條都「部分成立」的自我安慰。
  （賣方那張是另一組值域，來自匯流的裁決，不要混用。）
- **不要為了衝圖表比例畫沒有意義的圖。**
- **不要重做券商之間的綜合**，`crosscut` 已經做了。
- **不要自己裁決賣方主張。** 那是匯流每週在做的事，月報只彙總。
- **不要改 `build_hv.js`**——凍結檔，只用於重建 2026-07 以前的期別。
  它同時是 `healthcheck_hv.py` 的目錄指紋，刪掉它整支檢查會找不到自己。
- **不要在第 7 節寫回 cron**——那一節已經退場，但這條禁令跟著流程走。
